# 재직자 부문 승리전략 v1

## 전략 명제

**정확한 모델 하나가 아니라, 제조 현장의 의사결정을 개선하는 검증된 시스템을 제출한다.**

재직자 부문의 공식 평가 중점은 현장 적용성, 문제 해결성, 실효성, 확산 가능성이다. 2026년 공지 87호 첨부의 서면평가 배점은 기업문제·데이터 통합 20, AI 모델 및 통합성능 35, 영향요인·오류분석 중 정량분석 15, 현장 적용 기본설계 10, 창의성·확장성 10, 코드·재현성 10으로 총 100점이다. 데이터 통합·모델·오류분석에 70점이 배정되어도 나머지 30점은 현장 설계·확장·재현성을 요구한다. 2025년 30/70 배점은 역사적 참고자료로만 남긴다. 발표평가의 별도 상세 배점은 현재 공지에서 확인되지 않았다.

따라서 심사 대응용 논문은 단순히 최고 성능을 내는 모델보다 다음 근거를 제공해야 한다: 제조 현안과 데이터 선택의 연결, 융합 효과를 검증하는 제거실험, 조건별 오류와 한계, 실행 가능한 현장 조치 및 산출근거 있는 KPI, 타 공정으로의 적용 조건, 재현 가능한 코드·실험 절차. 논문은 방법의 근거이지 우리 팀 현장 KPI의 실증을 대체하지 않는다. 공식 근거는 [`competition-brief.md`](competition-brief.md)와 [`과제공개 첨부 HWPX`](../knowledge/kamp-public-2026-09-21/attachments/assignment-employee.hwpx)다.

## 우위를 만드는 여섯 축

### 1. 현장 문제를 비용 함수로 바꾼다

- 다운타임, 불량률, 재작업, 폐기량, 검사시간, 에너지, 납기 지연 중 과제와 직접 연결되는 KPI를 선택한다.
- 오탐과 미탐의 비용을 구분하고, 모델 임계값을 정확도가 아니라 기대 손실 최소화 관점에서 정한다.
- 현재 프로세스와 AI 적용 후 프로세스를 비교해 누가 언제 어떤 행동을 하는지 명시한다.

### 2. 데이터 누수 없는 검증을 설계한다

- 설비·LOT·제품·시간 단위가 섞이지 않도록 그룹 또는 시간 순서 기반 분할을 우선 검토한다.
- 전처리와 특징 선택은 학습 폴드 안에서만 수행한다.
- 단일 홀드아웃뿐 아니라 교차검증 분산과 부트스트랩 신뢰구간을 보고한다.
- 불균형 문제에서는 Accuracy만 쓰지 않고 F1, PR-AUC, Recall, 비용가중 지표를 함께 본다.

### 3. 강한 베이스라인에서 시작한다

- 표 데이터: 결측·이상치 규칙 + 로지스틱/트리 + CatBoost·LightGBM·XGBoost 계열 비교
- 시계열·진동: 윈도잉, 주파수/통계 특징 + 트리 모델을 먼저 만들고 1D-CNN·LSTM·오토인코더와 비교
- 비전: 단순 CNN/전이학습 베이스라인, 클래스 불균형과 데이터 증강을 분리 검증
- 이상탐지: 지도학습 가능 여부에 따라 Isolation Forest, One-Class, 오토인코더, 예측잔차 방식을 비교
- 복잡한 모델은 성능 향상과 현장 설명 가능성이 확인될 때만 채택한다.

### 4. 해석을 행동으로 연결한다

- SHAP·Permutation Importance·부분의존 등은 시각화로 끝내지 않고 공정 변수 조정 또는 점검 순서로 연결한다.
- 오류 분석표에 설비·제품·운전조건별 실패 패턴을 남긴다.
- 신뢰도 낮은 예측은 인간 검토로 보내는 보류 영역을 둔다.

### 5. 배포 가능성을 수치로 보여준다

- 입력 데이터 주기, 추론 지연, 계산 자원, 결측 시 처리, 알람 빈도, 재학습 조건을 명시한다.
- 드리프트·센서 고장·스키마 변경 감시 항목을 정의한다.
- PoC → 한 설비 → 한 라인 → 타 공장 확산 순서와 예상 비용·효과를 제시한다.

### 6. 확산성과 사업성을 설계한다

- 설비 고유 변수와 공통 변수를 분리한 표준 스키마를 만든다.
- 모델 본체보다 재사용 가능한 전처리·검증·모니터링 파이프라인을 강조한다.
- 타 업종 적용 시 필요한 최소 데이터, 라벨링 비용, 도입 기간을 추정한다.

## 과제 공개 전 준비

- [ ] 참가 신청과 재직 증빙 완료
- [ ] Python 환경 고정 파일과 재현 시드 정책 준비
- [ ] 표·시계열·비전용 공통 EDA 체크리스트 준비
- [ ] 그룹/시간 분할과 누수 점검 테스트 준비
- [ ] 베이스라인 학습·평가·추론 스크립트 골격 준비
- [ ] 실험 ID, 데이터 해시, 설정, 지표를 남길 실험 기록 양식 준비
- [ ] 보고서와 발표자료 골격 준비
- [ ] 현장 KPI·오탐/미탐 비용 인터뷰 질문 준비

## 과제 공개 후 48시간

1. 규정, 데이터 라이선스, 제출 형식, 평가지표를 먼저 고정한다.
2. 데이터 사전과 목표변수·의사결정 시점을 정의한다.
3. 누수 위험을 검토한 검증 분할을 확정한다.
4. 가장 단순한 베이스라인과 제출 파이프라인을 끝까지 통과시킨다.
5. 오류 분석으로 다음 실험 세 개만 우선순위화한다.

## 중단 기준

- 공개되지 않은 평가기준을 사실처럼 가정하지 않는다.
- 외부 데이터와 사전학습 모델은 규정이 허용하는지 확인 전 사용하지 않는다.
- 테스트셋을 반복 관찰하거나 데이터 출처·라이선스가 불명확한 자료를 사용하지 않는다.
- 성능 향상이 재현되지 않거나 현장 설명이 불가능하면 복잡도를 되돌린다.
