# Q.AI 에이전트 규칙

세 자리가 같이 쓰는 규칙 한 장이다. 자리 앱 안에 에이전트를 띄우지 않는다.
일은 각자 노트북의 Codex, Claude Code, Cursor 중 지금 켜 둔 도구에서 한다. IDE가 Cursor, VS Code, JetBrains, 터미널 중 어디여도 헤더와 JSON은 같다.
중간 상태는 자기 카드 한 장으로 자리로 올린다.
시작은 주제 셋업, 아이디어 10칸, 데이터 2종 설계가 끝난 뒤다. 그 전에는 아이디어 칸을 채우지 않는다.

## 읽을 곳

턴을 시작하기 전에 `GET /api/board`를 읽는다. `cards` 세 장이 이어받기이고, `run.id`가 이번 판 번호다.
헤더 `X-Room-Key`는 자리를 켠 사람의 터미널 `room` 줄이다. 이 파일에 적지 않는다.

## 올릴 곳

스킬 이름이나 이 규칙 파일이 바뀌면 카드보다 먼저 `POST /api/harness`를 보낸다.
헤더는 `X-Room-Key`와 `X-Seat-Key`다. 자리 키는 터미널의 자기 `seat` 줄이고, 이 파일에 적지 않는다.
`ruleHash`는 이 파일 바이트의 SHA-256 64자다. 스킬은 이름만 최대 12개다. 파일 내용은 올리지 않는다.
직전과 같으면 환경 키가 유지된다.

```json
{"seat":"정진우","run":"run-판번호","tool":"cursor","ide":"cursor","skills":["kamp-baseline-gbdt","kamp-leakage-audit"],"ruleHash":"64자","note":""}
```

그 다음 `POST /api/card`로 자기 자리를 덮어쓴다. 로그를 쌓지 않는다. `run`은 보드의 `run.id`와 같아야 한다.

```json
{"seat":"정진우","run":"run-판번호","phase":"EDA","now":"현장 2행까지 적힘","done":["jw-1 공정 적음","",""],"blocked":"","next":"jw-3","file":"docs/meetup-2026-09-26/정진우.md"}
```

`tool`은 `codex`, `claude-code`, `cursor` 중 하나다.
`ide`는 `cursor`, `vscode`, `jetbrains`, `terminal`, `other` 중 하나다.
도구를 바꾸거나 IDE를 바꾸면 환경 키가 새로 생긴다. 스킬 이름이 그대로여도 그렇다.
`phase`는 비움, `아이디어`, `EDA`, `모델링` 중 하나다. 비어 있고 스킬이 `kamp-nba` 하나면 아이디어, `kamp-fusion-ablation`이면 EDA, `kamp-baseline-gbdt`면 모델링으로 본다. 카드에 적힌 단어가 있으면 그 단어가 기준이다.
`seat`는 정진우, 엄예지, 최연식 중 자기 이름만.
`done`은 세 줄까지. `file`은 대회 폴더 안의 상대 경로다.
시작 전이거나 시작 키가 다르면 서버가 거절한다.

## 자리별 일

- 정진우, 엄예지: 현장 행. 공정, 무슨 일, 무엇을 잃나. 비어 있는 행을 에이전트가 채우지 않는다. 사람이 적은 뒤의 카드만 올린다.
- 최연식: 데이터 쌍. KAMP ID는 가이드북 목록에서 확인된 것만. 잇는 키를 모르면 모름.

## 회의 결정판

보드의 decision.votes는 세 사람의 최대 3표씩, decision.finalists는 사람이
담은 후보 최대 3개다. 둘 다 회의 초안이며 자동 추천이나 확정이 아니다.
에이전트는 이 상태를 읽을 수 있지만 /api/vote와 /api/shortlist를
호출하지 않는다. 후보가 비었으면 그대로 비었다고 보고한다.

## 경계

- 외부 모델 API 키를 자리에 넣지 않는다. 자리 키는 보드에서 자기 칸만 고르게 한다.
- 스킬 본문, 제품 안내, 훅, 플러그인을 자리에 올리지 않는다. 다른 사람의 도구에 깔지 않는다.
- `decision-log`, `data/raw`, 다른 사람의 행은 쓰지 않는다.
- VEDA는 경로로만 연다. 온톨로지로 만들거나 학습 입력으로 넣지 않는다.
- 자리의 문장은 초안이다. 잠금은 사람이 대회 `decision-log`에 적을 때 성립한다. `run`과 `env`는 그 잠금이 아니다.

## 팀 대화와 근거

messages와 evidence는 사람이 작성한 회의 자료다. 에이전트는 읽기만 하며 사람을 대신해 메시지·투표·후보·근거를 게시하지 않는다. 브라우저 쓰기는 개인 세션, 에이전트 쓰기는 기존 /api/card와 /api/harness 및 X-Seat-Key 계약을 따른다. 근거의 작성 여부 자체를 검증 완료로 간주하지 않는다.

## 사용자 취합본 반영 — 최신 입력 흐름

사용자가 취합한 아이디어 10개를 전달하면 담당 에이전트가 그 제공 자료에 한해 정리·반영한다. 기존의 개인별 직접 입력 및 시작 전 에이전트 입력 금지 규칙에 대한 이 범위의 예외다. 원문에 없는 손실·데이터 ID·경험·근거는 만들지 않는다. 슬롯 ID를 유지해 기존 댓글·투표 연결을 보존하고, 선택이 존재하는 아이디어 내용 변경은 먼저 영향을 설명한다. 투표·후보 선정은 계속 사람이 수행한다.

## 팀원이 실행하는 전역 설치

사용자 요청에 따라 /install.ps1은 본인 노트북에서 실행하는 한 줄 설치를 제공한다. 실행한 Windows 사용자에게만 qai 명령과 Q.AI 연결 스킬을 등록하고, 새 QAI-2026 작업 폴더에 대회 스킬·계약·역할을 둔다. 이 명시적 설치 흐름은 기존 ‘다른 사람의 도구에 깔지 않는다’ 규칙의 예외다. 에이전트가 다른 노트북에 원격 설치하는 기능은 아니다. 작업 폴더의 기존 수정 파일을 덮어쓰지 않는다.


## 2026-09-26 취합 20건

사용자 요청으로 A1–A10·B1–B10 전체를 비교한다. 이전 10칸 기준은 20칸으로 확장한다. 출처 번호·현재 대응·데이터 후보를 보존하며 후보 매칭은 미검증으로 표시한다. 원문과 실제 회의 내용은 로컬 보드에 저장한다.
