# 자리

## 각 노트북에 한 줄 설치

같은 Wi-Fi에서 보드에 본인 이름으로 들어간 뒤 **에이전트 설치 → 설치 명령 복사**를 누르고 PowerShell에 붙여 넣는다. 압축 해제, 관리자 권한, Node 설치는 필요 없다. Windows PowerShell 5.1 이상을 사용한다.

```powershell
irm 'http://172.30.1.58:3040/install.ps1' | iex
```

이 명령은 이름을 선택하도록 안내한다. 보드에서 복사한 명령에는 선택한 이름이 포함된다. Wi-Fi가 바뀌면 보드의 현재 주소에서 다시 복사한다.

- 사용자 전역 명령: `%LOCALAPPDATA%\QAI\agent\qai.cmd` (사용자 PATH에 등록)
- 본인 작업 폴더: `%USERPROFILE%\QAI-2026` (역할, 공통 계약, 대회 스킬 5개, 회의 상태)
- Codex·Cursor·Claude Code: 사용자 스킬 폴더에 Q.AI 전용 `qai-team` 연결 스킬 등록
- `qai open`: 작업 폴더 열기
- `qai sync`: 최신 회의 내용 받기
- `qai status`: 연결 상태 확인
- `qai connect http://새주소:3040`: Wi-Fi 변경 후 연결 주소 변경
- `qai update`: 설치된 파일 중 사용자가 수정하지 않은 파일 업데이트

에이전트 도구 자체, Python과 모델 의존성은 설치하지 않는다. 연결 스킬은 에이전트의 새 세션에서 사용한다. 사용자 수정 파일이 있으면 업데이트를 중단해 보존한다. 연결 키는 해당 Windows 사용자 계정의 DPAPI로 보호하며, 이름 선택은 팀 내 약속이고 신원 인증은 아니다. 서버가 켜져 있어야 동기화할 수 있다. 공개 npm/GitHub 패키지가 아닌 팀 LAN 배포 방식이다.

2026-09-26: 정진우 노트북에 실제 설치하고 `qai status`, `qai sync`로 보드 rev 26 수신을 확인했다. 다른 노트북의 설치와 LAN 접근은 아직 확인하지 않았다.

Q.AI 팀장이 진행을 보는 협업 페이지다. 모델 API를 호출하지 않고, 에이전트는 이 앱 안에서 돌지 않는다.

Codex, Claude Code, Cursor는 `agent-rule/RULE.md` 한 장만 따른다. IDE가 달라도 같은 주소와 같은 JSON이다. 중간 상태는 자리마다 카드 한 장이다. 도구나 스킬 이름이 바뀌면 그 카드 아래에 환경 키가 남는다.

지식은 `shelves.json`에 고른 선반만 연결한다. VEDA 본문과 FDE 온톨로지는 넣지 않는다.

이 폴더는 Agor 소스의 복사본이 아니다. Agor 저장소 안에 두지 않았고, 대회 제출 폴더에도 넣지 않는다.

## 10 → 3 결정판

아이디어 화면 아래에서 열 칸을 요약 비교한다. 정진우·엄예지·최연식이
각자 최대 3개에 표를 주면 득표 막대, 이름, 동점 상위권이 즉시 보인다.
회의에서 사람이 후보 3개를 따로 담고 요약을 복사해 검토한다.
빈 아이디어에는 표를 줄 수 없다. 표와 후보는 data/board.json에 남는
회의 초안이며, 대회 decision-log에 사람이 기록해야 잠금이 된다.

브라우저는 이름을 선택해 참여한다. 선택한 이름은 세션에 고정된다. 이름 선택은 본인 인증이 아니므로 각자 자기 이름을 사용한다. 에이전트는
투표와 후보를 읽기만 한다. qai-agent 입구에도 후보 초안과 참여 인원만
표시한다.

회의에서는 각자가 자기 이름을 선택해 현장 5행을 입력하고, 세 사람 모두
결정판에서 최대 3개씩 고른다. 동점과 손실·경험·보드의 KAMP 쌍 표시를
비교한 뒤 진행자가 후보 3개를 담는다. 회의 요약 복사로 잠금 기록의
초안을 만들고, 상위 3개의 상세 문제·행동·데이터 연결은 PPT 양식에
따로 채운다. 실제 아이디어가 들어오기 전에는 빈 칸을 유지한다.

## 두지 않은 것

토큰 비용이 생기는 실행기, 외부 모델 키, git 작업 트리, 터미널, 권한 단계, 일정 호출. Agor의 화면 코드와 서버 코드.

## 켜기

```powershell
cd F:\working\002.USEFUL\qai-jari
node server.js
```

브라우저 주소는 터미널에 나온다. 다른 노트북은 `localhost`가 아니라 그 PC의 주소와 3040 포트를 연다. 방 키는 같은 터미널의 `room` 줄이고, 파일은 `.room-key`다. 자리 키는 `seat` 줄이고, 파일은 `.seat-keys`다. 대회 폴더에는 넣지 않는다.

데이터는 `data/board.json`에 남는다.

경진 입구는 그 트리 안의 `qai-agent\자리.cmd`다. 부모에 `AGENT.md`와 경진 스킬이 있을 때만 갱신하고, 다른 경로에서는 멈춘다. 드라이브 문자는 적지 않는다. 다른 컴퓨터는 셸에만 `JARI_URL`과 `JARI_ROOM_KEY`를 넣는다. 원본 데이터와 키는 폴더에 넣지 않는다.

## 노트북 공동 참여 (2026-09-26)

호스트 한 대에서 서버를 유지하고 팀원들은 브라우저만 사용한다. 각 노트북에서 서버를 별도로 켜면 서로 다른 보드가 된다.

1. 같은 Wi-Fi/LAN에서 호스트의 IPv4 주소와 3040 포트로 접속한다. 현재 안내 주소는 http://10.70.194.173:3040 이며 네트워크가 바뀌면 주소도 확인한다.
2. 브라우저 참여에는 키 전달이 필요 없다. .room-key와 .seat-keys는 에이전트 연결에만 사용한다.
3. 각자 자기 이름을 선택해 들어간다. 서버 재시작 또는 24시간 경과 후 다시 이름을 선택한다.
4. 전체 대화 또는 아이디어 채널을 선택한다. 답글, @이름 강조, 새 글 수, 브라우저별 작성 초안을 제공한다. @표시는 앱 안 강조이며 외부 푸시 알림은 아니다.
5. 후보 근거는 버전 확인 후 저장한다. 동시 수정이면 기존 작성 내용을 보존하고 최신 내용을 불러오도록 알린다. 후보 담기도 이전 목록이 바뀌면 재선택한다.

브라우저 접속 표시는 heartbeat 기반이며 에이전트 프로세스 생존을 의미하지 않는다. 대시보드의 최근 보고 역시 프로세스 상태가 아니다.

Windows 방화벽이 막으면 호스트에서 allow-lan.ps1을 관리자 PowerShell로 실행한다. TCP 3040을 같은 서브넷에만 허용한다. 게스트 Wi-Fi의 기기 격리 환경에서는 같은 SSID여도 접속할 수 없다.
다른 장소에서는 LAN 주소로 접근할 수 없다. 승인된 사설 VPN 연결 후 주소와 방화벽 범위를 별도로 구성해야 한다. 인터넷 포트포워딩을 설정하지 않는다.

메시지와 근거는 data/board.json에 저장한다. 세션은 메모리에만 저장한다. 채팅은 삭제·첨부파일·외부 Slack 전송 기능을 제공하지 않는다.
참조: Slack threads https://slack.com/help/articles/115000769927-Use-threads-to-organize-discussions 및 Zulip topics https://zulip.com/help/introduction-to-topics 의 대화 구성 개념. 외부 코드를 복사하지 않았다.

## 간단한 회의 화면

첫 화면은 아이디어 적기이며 함께 고르기, 후보 비교로 이동한다. 회의 준비에서 주제·데이터 연결·시작 조건을 확인한다. 팀 작업 현황은 접어서 표시하고 대화는 오른쪽 아래에서 연다. 현재 탭은 해당 브라우저 세션에 유지된다. 후보 비교는 작성 근거이며 검증 완료 표시가 아니다.

디자인 참조: VEDA의 ui-ux-cx-bx-kawai-design-20260915/synthesis.md 및 design-judgment-ui-craft-ai-responsibility-20260924/normalized.md. 과업 성공, 상태·예외 설명, 시각 평가의 분리 원칙을 참고했다. PPTX 폴더 shadcn-studio-cleanroom/DESIGN.md의 간격·중립 표면·강조색 원칙을 참고했다. 참조 원문과 외부 코드를 복사하지 않았다.

## 취합형 아이디어 화면 (현재 흐름)

사용자가 아이디어 10개를 취합해 대화로 전달하면 담당 에이전트가 제공된 내용만 정리해 보드에 반영한다. 개인별 5개 입력 화면은 사용하지 않는다. 이전 슬롯 ID는 투표·댓글 연결을 보존하기 위해 내부에 유지하고, 화면에는 01~10으로 표시한다. 자료가 없는 항목은 취합 대기로 남긴다. 사람이 선택·투표하고 후보를 정한다. 보드 반영은 취합본 수신 시 수행하며 자동 파일 업로드 기능은 없다.
디자인 기준과 와이어프레임: UI_STANDARD.md.
