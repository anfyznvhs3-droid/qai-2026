## ID 21 — 품질 이상탐지·진단(도금욕)

### 확인된 데이터와 목적

- 제조 분야/공정: 이노징크 전기도금의 도금욕 공정.
- 수집 기간: 2021-09-06 ~ 2021-10-27, 수집 주기 5초.
- 입력 데이터: 테이블형, 수치 입력 7개 컬럼·50,094행. 가이드북상 변수는 `Index`, `LoT`, `Time`, `pH`, `Temp`, `Current`, `Voltage`.
- 출력 데이터: 수치 출력 3개 컬럼·33행. 가이드북은 별도의 Error Lot 목록 파일을 언급한다.
- 가이드북 설명상 공정 입력 변수는 `pH`, `Temp`, `Current`, `Voltage`, 품질 결과와 LOT 정보가 출력 측에 있다. 문서 안에서 독립/종속변수 설명이 일부 상충(`LoT`와 `LoT2`)하므로 원본 헤더와 조인 결과로 확정해야 한다.
- 가이드북 기본 분석은 Decision Tree와 Regression 계열이며, 혼동행렬·정확도·정밀도·재현율·민감도·특이도·F1을 사용한다.

### 우리가 풀 문제로 재정의할 것

**의사결정 단위:** LOT. 5초 행별 예측보다 “현재 LOT를 출하/후공정 전에 위험 LOT로 분류할 것인가”를 1차 목표로 둔다.

**권장 1차 타깃:** Error Lot 목록과 원시 입력의 `LoT`를 검증 조인한 `is_error_lot` 이진 라벨.

**현장 출력:** 위험 확률, 위험 판정 이유(top features), 조기 경보 시점, 점검 권고. 라벨이 연속 품질값이면 이진화하지 말고 별도 회귀 실험을 추가한다.

### 누수 방지 설계

1. Error Lot 목록이 생산 종료 후 생성된 목록이면, 그 목록은 학습 타깃으로만 사용하고 입력 특징에는 절대 넣지 않는다.
2. `LoT`, `Index`, `Date`, `Time`은 기본 모델에서 제외하거나 목적을 명시한다. 특히 `LoT`는 설비·시간 순서를 암기하는 대리변수가 될 수 있다.
3. 특징은 의사결정 시점 이전의 센서 구간에서만 만든다. 전체 LOT의 평균·최대값을 사용하면 미래 품질 정보가 섞일 수 있다.
4. 동일 LOT의 모든 행은 같은 fold에 둔다. 시간 외삽 성능은 마지막 날짜/LOT 홀드아웃으로 별도 측정한다.
5. 라벨 조인 후 미매칭 LOT, 중복 키, 출력이 여러 번 기록된 LOT를 표로 남긴다.

### 베이스라인 순서

| 단계 | 모델/특징 | 목적 |
|---|---|---|
| B0 | LOT별 정상 비율/다수 클래스 | 기준선과 라벨 불균형 확인 |
| B1 | `pH`, `Temp`, `Current`, `Voltage`의 초기 구간 평균·표준편차·최소/최대·기울기 + Logistic Regression | 설명 가능한 선형 기준선 |
| B2 | 동일 특징 + HistGradientBoosting/Random Forest | 비선형 상호작용 확인 |
| B3 | 시간 윈도우 특징과 센서 원인 기여도, 임계값 최적화 | 현장 조기경보 후보 |

### 점수와 승리 조건

- 주 지표: LOT 단위 PR-AUC, macro-F1 또는 위험 LOT recall. 공식 지표가 공개되면 매핑한다.
- 보조 지표: precision, specificity, calibration, 시간대별 recall, 오경보 수/LOT.
- 좋은 모델의 조건: 랜덤 행 분할 점수보다 LOT·시간 홀드아웃 점수가 크게 무너지지 않고, “왜 위험한지”를 센서별로 설명할 수 있어야 한다.

### `review_needed`

- Error Lot 파일의 정확한 파일명·컬럼·라벨 의미.
- 출력 33행과 입력 50,094행의 조인 키 및 22개 LOT 범위의 관계.
- 품질 판정이 LOT 종료 후인지, 공정 중 어느 시점에 가능한지.
- 공식 제출 타깃과 평가 지표.

**근거:** `Guidebook_품질 이상탐지, 진단(도금욕) AI 데이터셋.pdf`, pp. 5, 9–14, 23–24.

## ID 18 — 회전기계 고장유형

### 확인된 데이터와 목적

- rotor testbed에서 정상, 질량 불균형(Type 1), 지지 불량(Type 2), 두 고장 혼합(Type 3)의 4상태를 구현한다.
- 4개 센서, 2개 센서 그룹에서 약 140초의 진동 신호를 수집한다. 센서 사양의 주파수 span은 672 Hz, resolution은 1.3125 Hz로 기재되어 있다.
- 원시 데이터는 group 1·2 각각 5개 컬럼(`Time`, `Normal`, `Type 1`, `Type 2`, `Type 3`), 각 754,477행으로 설명된다. 센서별 sampling rate가 달라 처리 데이터는 선형보간 후 각 그룹 140,000행 × 4센서 형태가 된다.
- 라벨은 `Normal=0`, `Type 1=1`, `Type 2=2`, `Type 3=3`이다.
- 가이드북의 기본 모델은 DNN, CNN, RNN이며 보간·필터링·정규화 후 학습하지 않은 데이터로 성능을 확인한다.

### 우리가 풀 문제로 재정의할 것

**의사결정 단위:** 고정 길이 진동 윈도우 또는 하나의 실험/녹화 세션. 행 단위 분류가 아니라 “새 세션에서 고장 유형을 분류할 수 있는가”를 검증한다.

**권장 타깃:** 4-class 상태 라벨. 먼저 센서 그룹을 합쳐 일반화하고, 이후 한 센서 그룹을 통째로 홀드아웃해 센서 위치 변화에 대한 강건성을 확인한다.

### 누수 방지 설계

1. 140초 한 번의 기록에서 만든 윈도우가 train/test에 함께 들어가지 않게 한다. 원본 파일·실험 회차·고장 설정 회차를 그룹 ID로 보존한다.
2. 윈도우 분할은 특징 추출 전에 수행하고, 윈도우 경계가 기록 경계를 넘지 않게 한다.
3. interpolation, filtering, normalization 파라미터는 train 그룹으로만 fit하고 validation/test에는 transform만 한다.
4. 동일한 고장 설정, 동일한 센서 위치, 동일한 시간대의 거의 같은 파형이 복제됐는지 해시와 상관으로 점검한다.
5. 센서 그룹 1·2의 성능 차이와 교차 센서 일반화 성능을 별도로 보고한다. 랜덤 윈도우 점수는 참고용으로만 둔다.

### 베이스라인 순서

| 단계 | 모델/특징 | 목적 |
|---|---|---|
| B0 | 다수 클래스 | 불균형 기준선 |
| B1 | 시간영역 통계: RMS, peak-to-peak, kurtosis, crest factor, 표준편차, 센서 간 비율 + Logistic Regression/Random Forest | 빠르고 설명 가능한 기준선 |
| B2 | FFT band energy, dominant frequency, spectral entropy + HistGradientBoosting/LightGBM 계열 | 주파수 특징의 기여 확인 |
| B3 | 1D CNN 또는 CNN+attention | 원시 파형 경쟁 모델 |

### 점수와 승리 조건

- 주 지표: session/group holdout macro-F1, balanced accuracy, 클래스별 recall.
- 보조 지표: confusion matrix, 센서 그룹별 성능, 새 실험 회차 성능, 추론시간.
- 승리 조건: 랜덤 윈도우 분할이 아닌 실험 세션 홀드아웃에서도 Type 1·2·3을 균형 있게 구분하고, 1D CNN이 통계/FFT 기준선을 실제로 넘는 경우에만 복잡도를 정당화한다.

### `review_needed`

- 원시 CSV 파일이 몇 개의 실험/녹화 세션으로 구성되는지.
- 고장 상태별 반복 회차와 파일 간 중복 여부.
- 공식 테스트가 같은 testbed인지, 다른 센서 위치/회전 조건인지.
- 정상/고장 클래스별 실제 샘플 수와 공식 평가 지표.

**근거:** `Guidebook_회전기계 고장유형 AI 데이터셋.pdf`, pp. 5, 8–14, 23–24, 29–30.

## ID 19 — 공정운영 최적화

### 확인된 데이터와 목적

- 제조 분야/공정: 이노징크 전기도금의 산제 전처리 공정.
- 수집 기간: 2021-09-06 ~ 2021-10-27, 수집 주기 5초.
- 입력 데이터: 테이블형, 수치 입력 5개 컬럼·50,094행. `Index`, `LoT`, `Time`, `pH`, `Temp`.
- 출력 데이터: 3개 컬럼·726행. `Date`, `LoT`, `Process Rate`; Process Rate는 전처리 완료 결과물의 완성도를 정량화하는 지표로 설명되며 80.78~98.45 범위의 기술통계가 가이드북에 있다.
- 가이드북은 pH와 Temp를 독립변수, Process/Process Rate를 종속변수로 설명하고 Decision Tree를 기본 알고리즘으로 사용한다. 평가 설명은 혼동행렬·정확도라고 되어 있으나 Process Rate가 연속값으로 정의되어 있어 회귀 평가를 우선 검증해야 한다.

### 우리가 풀 문제로 재정의할 것

**의사결정 단위:** LOT 또는 공정 의사결정 시점. “주어진 운영 제약 안에서 Process Rate를 높이거나 목표 범위에 넣는 pH·Temp 조합을 추천할 수 있는가”로 정의한다.

**권장 1차 타깃:** `Process Rate` 회귀. 공식 과제가 분류형이면 목표 범주를 공식 정의에 맞춰 별도 branch로 만든다.

**현장 출력:** 예상 Process Rate, 추천 pH·Temp 범위, 예상 개선량, 제약 위반 여부, 적용 불확실성.

### 누수 방지 설계

1. `Process Rate`와 출력 파일의 `Date`, `LoT`는 타깃 조인/검증용이지 입력 특징으로 넣지 않는다.
2. Process Rate가 공정 종료 후 계산된 값이면 종료 후 pH·Temp를 사용하지 않는다. 의사결정 시점 전의 초기 구간 통계·추세만 사용한다.
3. 5초 원시 행을 랜덤 분할하지 말고 LOT 그룹 분할과 마지막 날짜/LOT 시간 홀드아웃을 함께 사용한다.
4. 출력 726행이 LOT당 단일 값인지, LOT 내 여러 시점의 값인지 확인한다. 후자이면 예측 시점과 타깃 시점을 명시하지 않은 모델은 폐기한다.
5. 최적화 추천은 관측 데이터의 범위 안에서만 수행한다. 학습 데이터 밖의 pH·Temp 조합을 외삽 추천하지 않는다.

### 베이스라인 순서

| 단계 | 모델/특징 | 목적 |
|---|---|---|
| B0 | 전체/최근 LOT 평균 Process Rate | 운영 기준선 |
| B1 | 초기 구간 pH·Temp의 평균·표준편차·최소/최대·기울기 + Ridge/Linear Regression | 방향성·해석 기준선 |
| B2 | 동일 특징 + Random Forest/HistGradientBoosting/Decision Tree | 비선형 효과 확인 |
| B3 | 관측 범위 내 grid search 또는 constrained optimizer + 불확실성/위반 패널티 | 실행 가능한 추천안 |

### 점수와 승리 조건

- 회귀 주 지표: LOT/시간 홀드아웃 MAE, RMSE, R². 실제 운영에서는 목표 범위 도달률과 공정 제약 위반률을 추가한다.
- 공식 과제가 분류형으로 확인되면 macro-F1, balanced accuracy, confusion matrix branch를 추가한다.
- 승리 조건: 예측 오차뿐 아니라 “왜 이 pH·Temp 영역을 추천하는지”, 추천 범위가 실제 관측 범위 안인지, 적용 시 품질·비용 trade-off가 무엇인지 설명한다.

### `review_needed`

- `Process Rate`가 LOT당 1개인지, LOT 내 다중 관측값인지.
- Process Rate 계산에 사용된 후공정/완료 시점 정보가 있는지.
- 공정 시간이 원본 데이터에 직접 포함되거나 추천 변수로 조절 가능한지.
- 가이드북의 정확도/혼동행렬 설명이 연속 타깃의 binning을 의미하는지.

**근거:** `Guidebook_공정운영 최적화 AI 데이터셋.pdf`, pp. 5, 7–14, 22–23.

## 선택 게이트

다음 세 가지를 실제 파일로 확인한 뒤 주력 후보를 하나로 좁힌다.

| 게이트 | 통과 조건 | 탈락/보류 조건 |
|---|---|---|
| G1 라벨 정합성 | 입력과 출력이 명확한 키로 조인되고 라벨 생성 시점이 설명됨 | 미매칭·중복·시점 불명확 |
| G2 누수 없는 검증 | LOT/세션/시간 홀드아웃을 구성할 수 있음 | 그룹 ID가 없어 분할 신뢰성 확보 불가 |
| G3 승리 가능성 | 기준선 대비 개선 + 원인/현장조치 설명 가능 | 높은 점수가 누수에만 의존하거나 재현 불가 |

현 단계의 우선 실행 순서는 **21 라벨 조인 감사 → 18 세션 경계 감사 → 19 Process Rate 정합성 감사**다. G1 또는 G2에서 막히는 후보는 즉시 폐기하지 않고 백업 후보와 비교한다.
